# 书籍 → 知识库 → 考试系统

## 这个 skill 解决什么问题

读完一本书，究竟记住了多少，是没法验证的。本skill 把书变成一套可考核的系统：

```
原书 → 章节切分 → 知识框架 + 两类考点卡片 → 考试网页（判分/错题本/90分通过）+ Anki闪卡
```

**验收标准是客观的**：正式考试 ≥90 分且错题本清零 = 视为掌握所选范围。

## 最高铁律：只做选择题

**全部题目一律是"点选"，不出现填空框、不出现长文本输入框。** 用户明确要求过：不要像上学一样填空，不要让人写一大段文字。

遇到看似只能填空/简答的考点，改造思路：

| 原考点形态 | 改造成选择题 |
|-----------|-------------|
| 填空（挖术语/步骤名/数字） | 题干保留情境，4个选项＝正确术语 + 3 个书中其他章节的似是而非术语 |
| 简答（要写要点） | 题干改为"以下哪项最完整/最符合……"，正确项覆盖原要点，另3 项是残缺或走偏的说法 |
| 步骤顺序 | 做成"下列顺序正确的是"，把正确顺序与打乱顺序作对比 |
| 概念辨析 | "以下说法错误的是"，四个选项都是书中说法，错的那个即为答案 |

## 其他铁律（违反即返工）

1. **一切以原文为据**。不编造书中没有的方法、术语、数据、案例。OCR 噪声要修正，但不得改写原意。
2. **先盘点再动手**。开跑前必须报告：格式、页数、是否文本型、章节数、总字数、目录层级。扫一眼就下结论 = 返工。
3. **交付前必须机械校验**：卡片 JSON 可解析、无重复 ID、题型全为选择题、题干无 `____` 残留、网页 JS 语法通过。校验不通过不交付。
4. **不中途停下**。用户要求批量处理时，一本书跑完再碰下一本。

## 执行流程

### 第0 步：估算规模，决定并行度

中文书按每页≈600 字、单个子代理可稳妥精读 ≈20–25 页估算：

```
所需子代理数 = ceil(正文页数 / 20)
```

| 正文页数 | 并行策略 |
|---------|---------|
| ≤ 40 页 | 单代理一次读完 |
| 40–150 页 | 2–4 个代理，按章节均分 |
| 150–400 页 | 4–8 个代理，每代理 3–6 章 |
| > 400 页 | 8个代理 + 先合并分部分批出卡 |

⚠️ 目录极密的（如工具书、百科全书）按"部分"分批，别让单个代理背 30 章。

### 第 1 步：切分全文

用 `pymupdf`（未安装则 `pip install pymupdf`）按 PDF 书签目录切章：

- 优先用 `doc.get_toc()`（书签），它自带层级；按目标层级（通常 lvl==2，即"章"）取条目
- 无书签则用正则识别章节标题行
- 每章存为 `chapters/NN_章名.txt`，同时产出 `划重点汇总.txt`（若有"本章小结/重点"类栏目）
- 每本书一个独立目录（建议统一放在一个书库里，便于 `build_portal.py` 聚合）：
  ```
  <你的书库>/<书名>/
  ```
  例：`D:\读书库\沟通的方法\`，下面所有产物都落在这个目录里

### 第 2 步：写知识框架（先建全局理解）

产出一份 `知识框架.md`：书的主旨 → 分部骨架 → 每章核心方法（用书中原方法名）→ 一段"全书一图流"。先有地图再看考点，否则卡片会碎片化。

### 第 3 步：派子代理产两类卡片

**每章两类题，都要出**（这是本流水线的关键设计——只考记忆会"背了不会用"）：

| 类型 | 每章数量 | 用途 |
|------|---------|------|
| `choice` | 9 | 概念原理：定义、步骤名、原则、顺序、辨析 |
| `scenario` | 2 | 真实情境该怎么做，干扰项优先取自本书其他章节的方法 |
| `case` | 1 | 书中真实案例体现什么原则 |

子代理硬性要求（写进 prompt）：
- **一律输出选择题**：`type` 只允许 choice / scenario / case，禁止 blank / short
- 禁止题干出现 `____`、禁止"请简述""请填空"这类需要输入文字的表述
- scenario 题干必须是自然口语化的真实工作/生活情境，**禁止**出现"根据本章""本书"
- scenario 干扰项优先取自**本书其他章节**的方法（跨章混淆才有难度）
- case 题必须取自该章原文出现的真实案例
- 保留 id、chapter、chapterTitle、difficulty、tags 字段
- 每代理负责 3–6 章，写入独立 JSON：`cards_01_06.json` / `applied_01_06.json`

卡片 schema：
```json
{"id":"c01-01","chapter":1,"chapterTitle":"章名","type":"choice|scenario|case",
 "difficulty":"easy|medium|hard","question":"...","options":["A. ...","B. ...","C. ...","D. ..."],
 "answer":"A","explanation":"依据原文的解析","tags":["关键词"]}
```

### 第 4 步：合并构建（用脚本，别手拼）

```bash
python <skill目录>/scripts/build_exam.py \
  --book-dir "<书库>/<书名>" \
  --title "《书名>" --subtitle "作者 · N部分N章" --pass-score 90
```

脚本会：合并去重 → 按章/题型排序 → 注入 `assets/考试系统_模板.html` → 输出四件套：
- `考点知识库.json`
- `考试系统.html`（自包含，双击即考，**内含知识大纲树**）
- `Anki闪卡_<书名>.txt`（TSV，标签=章节）
- `知识大纲.json` + `大纲速览.html`（大纲自动生成，见下）

脚本自带体检：解析失败/缺字段/非选择题/题干残留 `____`/选项不足会逐条报告并跳过，不会静默丢数据。

**大纲树是 build_exam 自动调起 build_outline.py 生成的**（无需单独跑）：从 `知识框架.md` 解析
「部分 → 章 → 核心知识点」三级结构，把每道题按关键词挂到最匹配的知识点上。构建报告会打印
挂载率；**兜底节点（未归类题目）占比 >30% 说明知识框架写得太空，要回去补细**。

想单独重跑大纲（如补完知识框架后）：
```bash
python <skill目录>/scripts/build_outline.py --book-dir "<书目录>"
```

### 第 5 步：校验与交付

1. `node --check` 校验抽取出的 `<script>` 语法
2. **DOM 桩回归测试**（可选但强烈建议）：把 `<script>` 抽出来、剥掉末尾 `initHome()`、
   套一层假 `document`/`localStorage`，在 Node 里直接调 `selCardIds()` / `effectivePool()` /
   `openReaderPool()`，验证勾选、取交集、错题重考、降级四条路径
3. 抽查 4 张卡片（覆盖三种题型）人工过目
4. `present_files` 交付考试网页（第一项）+ 框架 + 闪卡 + JSON
5. 回复中报告：页数/章节数/卡片数/知识点数/题型分布/校验结论，并说明大纲树怎么用来定向学

## 考试网页的能力（模板已实现，别重复造）

**知识大纲树（默认首页）**
- 三级折叠：部分 → 章 → 知识点；每节点显示题量 + 掌握度进度条
- **点选式定向学习**：勾任意知识点/整章/整部分 → 底部「只学选中的（速览）」直接看答案解析、
  「只考选中的」只考这几道 —— 不必整本都考
- 工具条：全部展开/收起、全选/清空、**只选未掌握**（按掌握度<90% 自动挑出薄弱知识点）、
  关键词搜索（命中自动展开所属章节）
- 每节点可「看内容」进速览阅读器；章节可「速览」整章
- **范围回显**：正式考试范围 = 大纲选中 ∩ 章节勾选 ∩ 题型筛选，并在首页明写当前多少题
  （避免"勾了知识点但考试范围没变"的假象）
- 第二个视图「章节速览」保留扁平章节勾选，兼容旧用法

**考试机制**
- 题型筛选：全部 / 概念原理题 / 应用题（场景+案例）
- 入口：正式考试（随机）、应用题专项、错题重考、浏览模式
- **全部题目点选作答**，选中即判分并出解析；数字键 1–6 快速选选项，回车/空格下一题
- 错题本：答错自动归档，重考只出错题，答对即移出；localStorage 按书名隔离
- 结果页：总分 + 通过判定 + 各章节正确率；首页：各章节掌握度百分比
- 未生成大纲时自动降级为纯章节视图（不会出现空白页或报错）

## 常见坑

| 坑 | 应对 |
|----|------|
| 子代理产出了填空/简答 | 构建脚本会直接拒绝并逐条报告，按「最高铁律」的对照表让子代理改造成选择题后重跑 |
| **无横线的填空思维化石**（如"被填进去的词是哪一个？""赞美=打追光+轻轻地+某一个词+常常地"） | 构建脚本的 `BLANK_PATTERNS` 会连同全角＿、空括号、"填空/依次应填/请简述"、"被填进/横线/空格"一起拦截；改法同上方对照表 |
| 子代理以"原 choice 题不能动"为由保留横线 | 明确告诉它：零填空铁律**优先于**原样保留，选项与答案可不动，题干必须改 |
| 记忆题与应用题 ID 撞车（都叫 c01-01） | 构建脚本按「章+题型」重新编号（c/x/k 前缀），原 ID 存入 `srcId` 留痕 |
| 沙箱里 `python -m pip install` 被中断 | 换用带完整解释器路径的调用方式（`"<解释器绝对路径>" -m pip install pymupdf`），并把安装放到后台执行；Windows 上优先用你环境里已隔离管理的 Python，避免污染系统环境 |
| `fitz` 导入告警 | 新版改用 `import pymupdf` |
| 中文文件名排序错乱 | 章节文件名统一补零 `01_`、`02_` |
| 子代理 JSON 带尾逗号/中文引号 | 让子代理用 `json.load` 自查后再交付；改写原文件前先备份成 `backup_*.json`（不要以 `cards_` 开头，否则会被构建脚本读进去） |
| 模板占位符注入 JS 报语法错| 纯文本占位符与字符串字面量占位符分开（`__BOOK_TITLE__` / `__BOOK_TITLE_JSON__`），交付前必须 `node --check` |
| 长书一次性塞爆上下文 | 严格按第 0 步估算并行，切勿单车到底 |
| **大纲知识点挂载率崩塌**（兜底节点 >30%） | 九成是知识框架写得太粗：①要点行只写"动作：多说我们少说你"这种没实词的抽象句，关键词抽不出 → 在框架里加**加粗术语**或**引号包住的方法名** ②要点用 `→` 连接时若分隔符漏了箭头会整行被丢 ③框架每章只写 3~4 条而一章有 15 题 → 脚本会自动用题目标签补足节点（标「标签」），但更好的做法是把框架写细 |
| 框架里混入 `---` 分隔线被当成知识点 | 解析器已跳过纯符号行；若你的框架用其他分隔符，扩展 `parse_framework` 里的 `re.fullmatch(r'[-=|\s:*]{3,}', s)` |
| 大纲节点名被截断成半句话 | 脚本已用「冒号前的实词」回退；若仍不理想，在框架里给该行加 `**加粗短名**` |
