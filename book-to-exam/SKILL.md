# 书籍 → 知识库 → 考试系统

```
原书 → 切章 → 知识框架（部分/章/知识点）→ 三类考点卡片 → 考试网页 + Anki闪卡
```

验收标准是客观的：**正式考试 ≥90 分且错题本清零 = 视为掌握所选范围。**

面向使用者的介绍见仓库 `README.md`，本文只写执行规则。

---

## 最高铁律：只做选择题

**全部题目一律点选，不出现填空框、不出现长文本输入框。**

| 原考点形态 | 改造成选择题 |
|-----------|-------------|
| 填空（挖术语/步骤名/数字） | 题干保留情境，4 个选项＝正确术语 + 3 个书中其他章节的似是而非术语 |
| 简答（要写要点） | 题干改为「以下哪项最完整/最符合……」，正确项覆盖原要点，另 3 项残缺或走偏 |
| 步骤顺序 | 做成「下列顺序正确的是」，正确顺序与打乱顺序作对比 |
| 概念辨析 | 「以下说法错误的是」，四个选项都是书中说法，错的那个即为答案 |

## 其他铁律

1. **一切以原文为据**。不编造书中没有的方法、术语、数据、案例。OCR 噪声要修正，但不得改写原意。
2. **先盘点再动手**。开跑前必须报告：格式、页数、是否文本型、章节数、总字数、目录层级。
3. **交付前必须机械校验**：卡片 JSON 可解析、无重复 ID、题型全为选择题、题干无 `____` 残留、网页 JS 语法通过。不通过不交付。
4. **不中途停下**。用户要求批量处理时，一本书跑完再碰下一本。

## 执行流程

### 第 0 步：估算规模，决定并行度

中文书按每页 ≈600 字、单个子代理可稳妥精读 ≈20–25 页估算：

```
所需子代理数 = ceil(正文页数 / 20)
```

| 正文页数 | 并行策略 |
|---------|---------|
| ≤ 40 页 | 单代理一次读完 |
| 40–150 页 | 2–4 个代理，按章节均分 |
| 150–400 页 | 4–8 个代理，每代理 3–6 章 |
| > 400 页 | 8 个代理 + 先合并分部分批出卡 |

⚠️ 目录极密的（工具书、百科全书）按「部分」分批，别让单个代理背 30 章。

### 第 1 步：切分全文

```bash
python <skill目录>/scripts/split_book.py "你的书.epub" --out "./<书库>/<书名>"
```

支持 **PDF / EPUB / TXT / Markdown**。产出 `chapters/NN_章名.txt`、`书籍信息.json`、`全文.txt`。

| 格式 | 切分依据 |
|------|---------|
| PDF | 优先书签目录 → 无书签回退正则（`--regex` 自定义） |
| EPUB | spine 顺序 + 标题层级**自动归并碎片**；「第一章」反复出现判为多册合集，**自动按册拆开** |
| TXT/MD | 正则扫 `第N章` / `Chapter N` |

三类书会**明确报错而不是静默产出垃圾**，遇到时按提示换书或先OCR：

- 扫描版 PDF（页数够但几乎提不出文字）→ 需要 OCR
- EPUB 标题是图片（HTML 里无文字标题）→ 换PDF 文字版
- 一级标题识别不足 3 个→ 不做归并，原样输出交人工判断

用户想省事时可以让TA 跑 `scripts/书架.py`：本地网页扫书 → 点书 → 切章 → 复制指令给你，
这是给「不知道路径、不想开终端」的用户准备的入口。

每本书一个独立目录，产物都落在里面。

### 第 2 步：写知识框架

产出 `知识框架.md`。**标题层级必须严格遵守**，否则大纲解析器取不到章节：

```markdown
## 第一部分：认识节奏

### ① 能量不是均质的 —— 能量曲线盘点法
- **能量三档**：高峰态 / 低谷态 / 休息态
- **黄金三小时**：起床后 2-4 小时的连续时段，留给最重要的深度工作
```

- 部分用 `## 第X部分：…`，章节用 `### ① 标题`（圈号 ①–⑳）
- 要点行**务必加粗术语**或用引号包住方法名——关键词抽不出来，题目挂载率会崩

### 第 3 步：派子代理产三类卡片

**每章两类题都要出**（只考记忆会"背了不会用"）：

| 类型 | 每章数量 | 用途 |
|------|---------|------|
| `choice` | 9 | 概念原理：定义、步骤名、原则、顺序、辨析 |
| `scenario` | 2 | 真实情境该怎么做，干扰项优先取自本书其他章节的方法 |
| `case` | 1 | 书中真实案例体现什么原则 |

子代理硬性要求（写进 prompt）：

- **一律输出选择题**：`type` 只允许 choice / scenario / case，禁止 blank / short
- 禁止题干出现 `____`、禁止"请简述""请填空"这类需要输入文字的表述
- scenario 题干必须是自然口语化的真实工作/生活情境，**禁止**出现"根据本章""本书"
- scenario 干扰项优先取自**本书其他章节**的方法（跨章混淆才有难度）
- case 题必须取自该章原文出现的真实案例
- 保留 id、chapter、chapterTitle、difficulty、tags 字段
- 每代理负责 3–6 章，写入独立 JSON：`cards_01_06.json` / `applied_01_06.json`

卡片 schema：

```json
{"id":"c01-01","chapter":1,"chapterTitle":"章名","type":"choice|scenario|case",
 "difficulty":"easy|medium|hard","question":"...","options":["A. ...","B. ...","C. ...","D. ..."],
 "answer":"A","explanation":"依据原文的解析","tags":["关键词"]}
```

出卡细则见 `docs/出题手册.md`。

### 第 4 步：合并构建

```bash
python <skill目录>/scripts/build_exam.py \
  --book-dir "<书库>/<书名>" \
  --title "《书名>" --subtitle "作者 · N部分N章" --pass-score 90
```

输出五件套：`考点知识库.json`、`考试系统.html`、`Anki闪卡_<书名>.txt`、`知识大纲.json`、`大纲速览.html`。

脚本自带体检：解析失败/缺字段/非选择题/题干残留 `____`/选项不足会逐条报告并跳过，不静默丢数据。
按「章+题型」重编号解决 ID 冲突（`c`/`x`/`k` 前缀，原 ID 存 `srcId`）。

**大纲树由 build_exam 自动调起 build_outline.py**（无需单独跑）。构建报告会打印挂载率；
**兜底节点（未归类题目）占比 >30% 说明知识框架写得太空，要回去补细**。

补完框架后可单独重跑：

```bash
python <skill目录>/scripts/build_outline.py --book-dir "<书库>/<书名>"
```

### 第 5 步：校验与交付

1. `node --check` 校验抽取出的 `<script>` 语法
2. **DOM 桩回归测试**：`node <仓库>/tools/regression_test.js`（实时读考试网页，覆盖勾选、取交集、错题重考、降级、进度导出/导入往返等 23 条路径）
3. 抽查 4 张卡片（覆盖三种题型）人工过目
4. `present_files` 交付考试网页（第一项）+ 框架 + 闪卡 + JSON
5. 回复中报告：页数/章节数/卡片数/知识点数/题型分布/校验结论，并说明大纲树怎么用来定向学

多书聚合总控页：

```bash
python <skill目录>/scripts/build_portal.py --lib-dir "<书库目录>"
```

## 考试网页的能力（模板已实现，别重复造）

大纲树（默认首页）：三级折叠 部分→章→知识点；勾选式定向学习（「只学选中的」看解析/「只考选中的」只考这几道）；
工具条含全部展开、全选、**只选未掌握**、搜索；**范围回显**＝大纲选中 ∩ 章节勾选 ∩ 题型筛选；
学习进度按部分聚合、可点开看章节并跳转；书本介绍卡 + 上手引导；无大纲时自动降级为章节视图。

考试机制：四种入口（正式/应用专项/错题重考/浏览）；点选即判分出解析；数字键 1–6 选选项、回车下一题；
错题本自动归档、答对移出；结果页给总分+分章正确率；localStorage 按书名隔离。

**改这个模板前先读源码**，别凭想象加功能——上述行为都已在 `assets/考试系统_模板.html` 里实现。

## 排错与坑

完整清单见 `docs/校验清单.md`（交付前必跑）与 `docs/出题手册.md`（出卡规范）。最高频的四个：

| 坑 | 应对 |
|----|------|
| 子代理产出填空/简答，或**无横线的填空思维化石**（"被填进去的词是哪一个？"） | `build_exam.py` 的 `BLANK_PATTERNS` 会连同全角＿、空括号、"填空/依次应填/请简述"、"被填进/横线/空格"一起拒收；按「最高铁律」对照表改造成选择题后重跑 |
| **大纲挂载率崩塌**（兜底节点 >30%） | 九成是知识框架太粗：①要点行只写没实词的抽象句 → 加**加粗术语**或**引号**包住方法名 ②要点用 `→` 连接时别漏箭头，否则整行被丢 ③每章只写 3~4 条而一章有 15 题 → 脚本会用题目标签补足节点，但更好的做法是把框架写细 |
| 章节写成 `### 第1章 …` 导致大纲0 章 | 解析器只认 `### ① …` 圈号格式（见第2 步） |
| **改了模板但用户看到的还是旧界面** | 书籍输出目录里可能残留一份改造前的 `考试系统_模板.html` 副本，用户打开的是它而不是 `考试系统.html`。**交付前务必确认用户实际会点开的那个文件**：`ls <书籍目录>` 应只有构建产物，没有模板副本 |
| 副标题里"N部分M章"与书本卡的章节数显示两次 | `build_exam.py` 已自动剥离副标题中的结构数字，只留作者/版本。若又出现，检查是否绕过了构建脚本直接改 HTML |
| 模板占位符注入 JS 报语法错 | 纯文本占位符与字符串字面量分开（`__BOOK_TITLE__` / `__BOOK_TITLE_JSON__`），**只用在 HTML 正文、别放进 JS 代码里**，交付前必须 `node --check` |

零填空扫描要**扫题库 JSON**（question/options/explanation），不要扫整份 HTML——
JS 函数调用 `selectWeak()` 会命中"空括号"，快捷键提示会命中"空格"，必然误报。

其他环境类问题：JSON 尾逗号、子代理上下文超限见 `README.md` 坑表；
`pymupdf` 安装中断 / `fitz` 导入告警 / `doc.get_toc()` 版本差异都表现为「切章回归大面积 SKIP」，解法见坑表同一行。
中文文件名排序只影响人工浏览——构建脚本内部按「章节号 + 题型」排序，不受影响。
