# book-to-exam-skill

> **把一本书变成一套可以「考过才算读懂」的系统。**
> 纯选择题 · 交互式考试网页 · 知识大纲树 · Anki 闪卡 —— 全部离线生成，零外部依赖。

```
原书 PDF/EPUB/txt
   ↓  章节切分
   ↓  知识框架（部分 → 章 → 知识点）
   ↓  三类考点卡片（概念 / 场景 / 案例）
   ↓
考试系统.html   ← 双击即考，自包含单文件
Anki闪卡.txt   ← 可直接导入 Anki
```

**验收标准是客观的**：正式考试 ≥ 90 分且错题本清零 = 视为掌握所选范围。

---

## 这套系统解决什么问题

读完一本书，究竟记住了多少，是没法验证的。

「以考代学」把主观的"感觉读懂了"换成一个可判定的数字：90 分。
更关键的是，它把整本书拆成了**可勾选的知识大纲**——你不必考整本书，
可以只勾「结构化倾听」这一个知识点，两分钟考完，立刻知道这一节到底掌握了没有。

---

## 三个核心设计

### 1. 全程只做选择题（零输入框）

**没有填空框，没有长文本框。** 全部题目一律点选，选中即判分并出解析。

遇到看似只能填空或简答的考点，改造思路：

| 原考点形态 | 改造成选择题 |
|-----------|-------------|
| 填空（挖术语/步骤名/数字） | 题干保留情境，4 个选项 ＝ 正确术语 + 3 个书中其他章节的似是而非术语 |
| 简答（要写要点） | 题干改为「以下哪项最完整/最符合……」，正确项覆盖原要点，另 3 项残缺或走偏 |
| 步骤顺序 | 做成「下列顺序正确的是」，正确顺序与打乱顺序作对比 |
| 概念辨析 | 「以下说法错误的是」，四个选项都是书中说法，错的那个即为答案 |

构建脚本会用一组高精度正则（含全角＿、空括号、「被填进去的词是」这类**无横线填空思维化石**）
拦截任何需要打字作答的题目并拒收，从机制上杜绝"看起来像选择题、实际要填空"的漏网之鱼。

### 2. 三种题型，每章都要出

| 类型 | 每章数量 | 用途 |
|------|---------|------|
| `choice` | 9 | 概念原理：定义、步骤名、原则、顺序、辨析 |
| `scenario` | 2 | 真实情境该怎么做，**干扰项优先取自本书其他章节的方法** |
| `case` | 1 | 书中真实案例体现什么原则 |

只考记忆会"背了不会用"。场景题的干扰项跨章取方法，跨章混淆才有真实难度。

### 3. 知识大纲树：勾选式定向学习

首页默认就是三级知识树：**部分 → 章 → 知识点**，每个节点显示题量与掌握度进度条。

- 勾任意知识点 / 整章 / 整部分 → 「**只学选中的**」直接看答案解析，「**只考选中的**」只考这几道
- 工具条：全部展开/收起、全选/清空、**只选未掌握**（掌握度 < 90% 自动挑出薄弱点）、关键词搜索
- **范围回显**：正式考试范围 ＝ 大纲选中 ∩ 章节勾选 ∩ 题型筛选，首页明写当前多少题
  （避免"勾了知识点但考试范围没变"的假象）

大纲树由 `build_outline.py` 从知识框架自动解析并把题目挂到最匹配的知识点上，
构建报告会打印**挂载率**；兜底节点占比过高说明知识框架写得太粗，需要回去补细。

## 快速开始

### 一分钟验证安装是否正常

仓库带一套**自包含的演示数据**（自编内容，非任何真实出版物）：

```bash
git clone https://github.com/gaoren7716-lab/book-to-exam-skill.git
cd book-to-exam-skill

# 构建演示书籍 → 生成考试系统.html
python book-to-exam/scripts/build_exam.py \
  --book-dir "examples/demo-节奏管理" \
  --title "《节奏管理》" --subtitle "示例自编 · 2部分4章" --pass-score 90

# 打开考试网页
start examples/demo-节奏管理/考试系统.html      # Windows
open  examples/demo-节奏管理/考试系统.html      # macOS

# 跑交互回归测试（12 项，应全部 PASS）
cd examples/demo-节奏管理 && node ../../tools/regression_test.js
```

预期输出：48 题（概念 36 + 场景 8 + 案例 4）、4 章、2 部分 / 4 章 / 23 知识点、挂载 48/48。

### 处理自己的书

**依赖**：Python 3.8+（PDF 切分需 `pip install pymupdf`，其余脚本零第三方依赖）。Node 可选，仅回归测试需要。

#### 第 0 步：估算规模，决定并行度

中文书按每页 ≈ 600 字、单个子代理可稳妥精读 ≈ 20–25 页估算：

```
所需子代理数 = ceil(正文页数 / 20)
```

| 正文页数 | 并行策略 |
|---------|---------|
| ≤ 40 页 | 单代理一次读完 |
| 40–150 页 | 2–4 个代理，按章节均分 |
| 150–400 页 | 4–8 个代理，每代理 3–6 章 |
| > 400 页 | 8 个代理 + 先合并分部分批出卡 |

⚠️ 目录极密的（工具书、百科全书）按「部分」分批，别让单个代理背 30 章。

#### 第 1 步：切分全文

用 `pymupdf` 按 PDF 书签目录切章（`doc.get_toc()` 优先，它自带层级），
无书签则用正则识别章节标题行。每本书一个独立目录：

```
<你的书库>/<书名>/
```

#### 第 2 步：写知识框架

产出一份 `知识框架.md`。**标题层级必须严格遵守**，否则大纲解析器取不到章节：

```markdown
## 第一部分：认识节奏

### ① 能量不是均质的 —— 能量曲线盘点法
- **能量三档**：高峰态 / 低谷态 / 休息态
- **黄金三小时**：起床后 2-4 小时的连续时段，留给最重要的深度工作
```

- 部分用 `## 第X部分：…`
- 章节用 `### ① 标题`（圈号 ①–⑳）
- 要点行**务必加粗术语**或用引号包住方法名——关键词抽不出来，题目挂载率会崩

#### 第 3 步：派子代理产卡片

每章 9 + 2 + 1 题，写入独立 JSON（`cards_01_06.json` / `applied_01_06.json`）：

```json
{"id":"c01-01","chapter":1,"chapterTitle":"章名","type":"choice",
 "difficulty":"easy","question":"...","options":["A. ...","B. ...","C. ...","D. ..."],
 "answer":"A","explanation":"依据原文的解析","tags":["关键词"]}
```

子代理硬性要求：

- `type` 只允许 `choice` / `scenario` / `case`，**禁止 `blank` / `short`**
- 题干禁止 `____`，禁止"请简述""请填空"这类需要输入文字的表述
- scenario 题干必须是自然口语化的真实工作/生活情境，**禁止**出现"根据本章""本书"
- scenario 干扰项优先取自**本书其他章节**的方法
- case 题必须取自该章原文出现的真实案例

#### 第 4 步：合并构建

```bash
python book-to-exam/scripts/build_exam.py \
  --book-dir "<书库>/<书名>" \
  --title "《书名>" --subtitle "作者 · N部分N章" --pass-score 90
```

产出：`考点知识库.json`、`考试系统.html`、`Anki闪卡_<书名>.txt`、`知识大纲.json`、`大纲速览.html`。

脚本自带体检：解析失败 / 缺字段 / 非选择题 / 题干残留填空痕迹 / 选项不足会逐条报告并跳过，
**不会静默丢数据**。ID 按「章 + 题型」重新编号（`c` 单选 / `x` 场景 / `k` 案例），原 ID 存入 `srcId` 留痕。

补完知识框架后可单独重跑大纲：

```bash
python book-to-exam/scripts/build_outline.py --book-dir "<书库>/<书名>"
```

#### 第 5 步：校验与交付

1. `node --check` 校验抽取出的 `<script>` 语法
2. **DOM 桩回归测试**（`tools/regression_test.js`）：套一层假 `document`/`localStorage`，
   在 Node 里直接调 `selCardIds()` / `effectivePool()` / `openReaderPool()`，验证勾选、取交集、错题重考、降级
3. 抽查 4 张卡片（覆盖三种题型）人工过目
4. 交付考试网页 + 框架 + 闪卡 + JSON

#### 附：多书聚合总控页

```bash
python book-to-exam/scripts/build_portal.py --lib-dir "<书库目录>"
```

扫描书库下所有已建书籍，生成「书架考试总控.html」：书名、题量、章节数、题型构成、入口。

## 作为 Agent Skill 使用

把 `book-to-exam/` 整个目录放进你的 skills 目录即可：

```
~/.workbuddy/skills/book-to-exam/     # WorkBuddy
~/.claude/skills/book-to-exam/        # Claude Code
```

`SKILL.md` 带有 YAML frontmatter 与触发词，当你说"把这本书做成考试系统""以考代学"
"生成考点""我要背这本书"时会自动触发。

## 考试网页的能力

**知识大纲树（默认首页）**
- 三级折叠：部分 → 章 → 知识点，每节点显示题量 + 掌握度进度条
- 点选式定向学习：勾选 → 「只学选中的（速览）」看答案解析、「只考选中的」只考这几道
- 「只选未掌握」按掌握度 < 90% 自动挑出薄弱知识点
- 关键词搜索，命中自动展开所属章节
- 范围回显：正式考试范围 ＝ 大纲选中 ∩ 章节勾选 ∩ 题型筛选
- 未生成大纲时**自动降级**为纯章节视图（不会出现空白页或报错）

**考试机制**
- 题型筛选：全部 / 概念原理题 / 应用题（场景 + 案例）
- 入口：正式考试（随机）、应用题专项、错题重考、浏览模式
- 全部题目点选作答，选中即判分并出解析；数字键 1–6 快速选选项，回车/空格下一题
- 错题本：答错自动归档，重考只出错题，答对即移出；`localStorage` 按书名隔离
- 结果页：总分 + 通过判定 + 各章节正确率；首页：各章节掌握度百分比

## 常见坑

| 坑 | 应对 |
|----|------|
| 子代理产出了填空/简答 | 构建脚本直接拒绝并逐条报告，按 README 的对照表改造成选择题后重跑 |
| **无横线的填空思维化石**（"被填进去的词是哪一个？"） | `BLANK_PATTERNS` 连同全角＿、空括号、"填空/依次应填/请简述"、"被填进/横线/空格"一起拦截 |
| 子代理以"原题不能动"为由保留横线 | 明确告知：**零填空铁律优先于原样保留**，选项与答案可不动，题干必须改 |
| 记忆题与应用题 ID 撞车 | 构建脚本按「章+题型」重新编号，原 ID 存入 `srcId` |
| 模板占位符注入 JS 报语法错 | 纯文本占位符与字符串字面量占位符分开（`__BOOK_TITLE__` / `__BOOK_TITLE_JSON__`），交付前必须 `node --check` |
| 长书一次性塞爆上下文 | 严格按第 0 步估算并行，切勿单车到底 |
| **大纲知识点挂载率崩塌**（兜底 > 30%） | 九成是知识框架太粗：①要点行只写"动作：多说我们少说你"这种没实词的抽象句 → 加**加粗术语**或**引号**包住方法名 ②要点用 `→` 连接时若分隔符漏了箭头会整行被丢 ③每章只写 3~4 条而一章有 15 题 → 脚本会用题目标签自动补足节点，但更好的做法是把框架写细 |
| 章节标题写成 `### 第1章 …` 导致大纲 0 章 | 解析器要求 `### ① …` 圈号格式，见第 2 步 |
| 中文文件名排序错乱 | 章节文件名统一补零 `01_`、`02_` |
| 子代理 JSON 带尾逗号/中文引号 | 让子代理用 `json.load` 自查后再交付；改写原文件前先备份成 `backup_*.json`（不要以 `cards_` 开头，否则会被构建脚本读进去） |

## 铁律速记

1. **一切以原文为据** —— 不编造书中没有的方法、术语、数据、案例
2. **先盘点再动手** —— 开跑前必须报告：格式、页数、是否文本型、章节数、总字数、目录层级
3. **交付前必须机械校验** —— JSON 可解析、无重复 ID、题型全为选择题、无填空残留、JS 语法通过
4. **不中途停下** —— 用户要求批量处理时，一本书跑完再碰下一本
