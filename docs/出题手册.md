# 出题手册

写卡片时照这份手册走，能避开 90% 的返工。

---

## 卡片 Schema

```json
{
  "id": "c01-01",
  "chapter": 1,
  "chapterTitle": "能量不是均质的",
  "type": "choice",
  "difficulty": "easy",
  "question": "……",
  "options": ["A. …", "B. …", "C. …", "D. …"],
  "answer": "B",
  "explanation": "依据原文的解析",
  "tags": ["关键词1", "关键词2"]
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| `id` | ✅ | 章节内唯一即可，构建脚本会按「章+题型」重编号，原值存入 `srcId` |
| `chapter` | ✅ | 整数章号 |
| `chapterTitle` | ✅ | 与知识框架里的章标题一致 |
| `type` | ✅ | **只能** `choice` / `scenario` / `case` |
| `difficulty` | ✅ | `easy` / `medium` / `hard` |
| `question` | ✅ | 单行，**不得含任何填空痕迹** |
| `options` | ✅ | 4 个，每项必须以 `A. ` `B. ` `C. ` `D. ` 开头 |
| `answer` | ✅ | 单个字母，必须能在某个选项开头定位到 |
| `explanation` | ✅ | 依据原文，不是"因为它很重要"这类空话 |
| `tags` | — | 供大纲挂载用，填**方法名/术语**，不要填"重点""易错" |

## 铁律一：只做选择题

**不出现填空框，不出现长文本框。** 遇到看似只能填空或简答的考点，按下表改造：

| 原考点形态 | 改造成选择题 |
|-----------|-------------|
| 填空（挖术语/步骤名/数字） | 题干保留情境，4 个选项 ＝ 正确术语 + 3 个**书中其他章节**的似是而非术语 |
| 简答（要写要点） | 题干改为「以下哪项最完整 / 最符合……」，正确项覆盖原要点，另 3 项残缺或走偏 |
| 步骤顺序 | 做成「下列顺序正确的是」，正确顺序与打乱顺序作对比 |
| 概念辨析 | 「以下说法错误的是」，四个选项都是书中说法，错的那个即为答案 |

### 无横线的填空思维化石（重点）

最难防的不是 `____`，而是**没有横线但依然要你"想起那个词"**的题：

```
❌ 赞美 = 打追光 + 轻轻地 + 某一个词 + 常常地
❌ 「被填进去的词是哪一个？」
✅ 书中所说的「肯定反射」具体指哪一项做法？
```

构建脚本的 `BLANK_PATTERNS` 会拦截以下信号，命中即拒收该卡片：

| 信号 | 例子 |
|------|------|
| 半角 / 全角横线 | `____` `＿＿＿＿` |
| 空括号 | `（ ）` `( )` |
| 主观作答措辞 | `填空` `空缺处` `依次应填` `请填写` `请简述` `请回答` `试述` |
| 填入某词句式 | `被填进` `被填入` `填入的是` `填进去的词` |
| 留白标记 | `横线` `空格` `划掉` `此处填` `方括号` |

⚠️ 刻意**不拦**这些正当表达：「空缺岗位」「以下哪个词不属于……」——
一刀切会误杀合法选择题。

### 子代理以"原题不能动"为由保留横线时

明确告诉它：**零填空铁律优先于原样保留。选项与答案可以不动，题干必须改。**

## 铁律二：三种题型各有写法

### `choice` — 概念原理（每章 9 道）

覆盖：定义、步骤名、原则、顺序、辨析。

```
✅ 「缓冲原则」对排期的要求是：
   A. 只估算理想耗时即可
   B. 实际排期在理想耗时基础上乘以约1.5倍系数
   C. 把日程排满，不留空白
   D. 排期只按最坏情况计算
```

三个干扰项要**似是而非**：从书中其他概念拆解、语义相反、或"看似合理但书中没这么说"。

### `scenario` — 场景应用（每章 2 道）

- 题干必须是**自然口语化的真实工作/生活情境**
- **禁止**出现"根据本章""本书""作者认为"
- 干扰项**优先取自本书其他章节的方法**——跨章混淆才有真实难度
- 4 个选项都是可执行的具体动作，不是抽象评价

```
✅ 同事把你从写季度方案拉到会议室开三个小时的讨论会，而方案今天必须交。
   你的方案思路正好卡住。哪种做法最合理？
   A. 忍着参加，会后靠熬夜把方案补完
   B. 争取把讨论会压缩到四十分钟，会议期间用手机回复零散消息
   C. 说明方案截止时间，请求把讨论会挪到明天上午，并在这段时间完成方案核心部分
   D. 会议上先不做方案，等晚上低能量时再写
```

### `case` — 书中真实案例（每章 1 道）

- **必须**取自该章原文出现的真实案例，不许编
- 题干讲清案例事实，问"这体现/验证了哪条原则"
- 4 个选项都是书中原则，正确项是本案例真正体现的那条

## 铁律三：`explanation` 必须有信息量

```
❌ 因为这个知识点很重要。
❌ 这是书中的核心观点。
✅ 低谷期的判断力显著下降，此时做重要决策属于高风险行为。
```

好的 explanation 应该让**答错的人读完就懂**，而不只是知道"我选错了"。

---

## 铁律四：`tags` 决定大纲挂载率

大纲树靠 `tags` 和知识框架里的术语做匹配。填错会导致题目全部掉进"本章其他要点"兜底节点。

- ✅ 填**方法名/术语**：`["能量曲线", "切换成本"]`
- ❌ 填**元信息**：`["重点", "易错", "难点", "高频"]`

兜底节点占比 > 30% 时，先怀疑两件事：
1. 卡片 `tags` 没填方法名
2. 知识框架的要点行只写了抽象句（"动作：多说我们少说你"），抽不出实词

## 提交前自查

```bash
python -c "
import json,glob,re,sys
BLANK=[r'_{2,}',r'＿+',r'[（(]\s*[）)]',r'填空',r'空缺处',r'依次应填',r'请填写',r'请简述|请回答|试述',r'被填进|被填入|填入的是|填进去的词',r'横线|空格|划掉|此处填|方括号']
bad=0
for f in glob.glob('cards_*.json')+glob.glob('applied_*.json'):
    for c in json.load(open(f,encoding='utf-8')):
        if c['type'] not in ('choice','scenario','case'): print('题型',c['id'],c['type']); bad+=1
        if len(c['options'])!=4: print('选项数',c['id'],len(c['options'])); bad+=1
        if not any(o.strip().startswith(c['answer']) for o in c['options']): print('答案',c['id']); bad+=1
        scan=c['question']+' '+' '.join(c['options'])
        hit=[p for p in BLANK if re.search(p,scan)]
        if hit: print('填空痕迹',c['id'],hit); bad+=1
print('问题数:',bad)
"
```
