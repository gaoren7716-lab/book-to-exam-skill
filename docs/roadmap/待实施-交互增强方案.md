## 零、先说清当前的三个真实短板

审阅代码后确认，这三点决定了哪些增强真正有价值：

### 短板 1：90 分可以被"应试"拿到

```js
// build_exam 模板 · gradeChoice()
document.querySelectorAll('.opt').forEach((o,i)=>{
  if(i===ansIdx) o.classList.add('right');   // 答完立刻高亮正确答案
  else if(i===picked) o.classList.add('wrong');
});
finishGrading(correct, `正确答案：${c.options[ansIdx]}...`);
```

答错时**当场告诉你正确答案**。在同一场考试里，第二次遇到同样内容时你已经知道答案了。
再加上随机排序（`pool.sort(()=>Math.random()-.5)`）只打乱题序、不打乱选项序，
「背选项位置」这条路是通的。系统目前**无法区分"真懂"和"蒙对"**。

### 短板 2：掌握度是快照，不抗遗忘

```js
let state = {wrongBook:{}, history:[], answered:{}};
// ...
state.answered[exam.pool[exam.idx].id] = correct ? 'right' : 'wrong';   // 只存字符串
```

`answered` 只记对错，**没有时间戳**（`history` 数组虽然记了日期，但只记整场考试的汇总，
不关联到具体题目）。所以：

```js
function ptStats(pt){
  pt.cards.forEach(id=>{ if(state.answered[id]==='right') right++; });   // 一次答对 = 永久掌握
```

一道题只要答对过一次，掌握度就 100%，**永不复查**。隔一周再考，靠的是你还记得上次答了什么。

### 短板 3：答错只存"错"，不存"为什么错"

```js
if(!correct && exam.mode !== 'browse') state.wrongBook[exam.pool[exam.idx].id] = true;
```

`wrongBook` 是个 `Set` 语义的布尔表。四种性质完全不同的错误——概念混淆、彻底没记住、
审题失误、犹豫蒙的——被压成同一个 `true`。错题本只能告诉你"错了"，没法告诉你"该怎么补"。

## 一、置信度标记（优先级 1）

### 解决什么
把「蒙对」从「答对」里剥离出来。这是让 90 分重新变得可信的前提。

### 交互形态

答**之前**在题干下方出现两枚按钮，答完即消失：

```
┌────────────────────────────────────────┐
│  第 3 / 48 题              场景题       │
│  同事把你从写季度方案拉到会议室…        │
│                                        │
│  ① 此刻的把握程度：                    │
│  ┌──────────┐  ┌──────────┐            │
│  │ 有把握    │  │ 蒙的/不确定 │           │
│  └──────────┘  └──────────┘            │
│                                        │
│  A. 忍着参加，会后靠熬夜补完            │
│  B. 争取把讨论会压缩到四十分钟           │
│  C. 说明截止时间，请求挪到明天上午  ← 1  │
│  D. 会议上先不做，等晚上低能量时再写     │
└────────────────────────────────────────┘
```

快捷键：`Q` = 有把握，`W` = 蒙的。不点也能作答（默认按「有把握」计入，保持原有手感）。

### 数据结构改动

```js
// 改动前
state.answered[id] = 'right' | 'wrong'

// 改动后：answered 升级为对象，带时间戳与置信度
state.answered[id] = {
  r: 'right' | 'wrong',      // 结果
  c: 1 | 0,                  // 置信度：1=有把握 0=蒙的
  t: 1752000000000           // 本次作答时间戳（毫秒）
}
```

⚠️ **向后兼容**：`loadState()` 里对旧格式（字符串）做一次迁移，
旧记录一律视为 `{r:旧值, c:1, t:0}`，`t:0` 视为"时间未知"。

### 新增统计口径

| 指标 | 口径 | 意义 |
|------|------|------|
| 真掌握 | 答对 且 置信=有把握 | 唯一可信的掌握证据 |
| 蒙对 | 答对 但 置信=蒙的 | **高危**，需重考 |
| 糊涂错 | 答错 但 置信=有把握 | 危险信号，概念已混淆 |
| 诚实错 | 答错 且 置信=蒙的 | 正常学习曲线，无需干预 |

### 涉及改动

| 文件 | 改动 |
|------|------|
| `assets/考试系统_模板.html` | 新增 `setConfidence(v)`；`showQ()` 插入按钮与状态；`finishGrading()` 写入新结构；`loadState()` 加迁移；`ptStats()` 改用真掌握口径 |
| `scripts/build_exam.py` | 无需改动（纯模板侧） |
| 题库 JSON | **无需改动** |

### 验收标准
- 旧版 localStorage 记录能正常加载、不报错（迁移生效）
- 答完 5 题后 `state.answered` 每条含 `r`/`c`/`t` 三字段
- 「只选未掌握」改为按**真掌握**筛，蒙对题仍会被选中
- 键盘 `Q`/`W` 可用，且不影响现有 `1`–`6` 与回车

## 二、错因归因（优先级 2）

### 解决什么
把 `wrongBook` 的 `true` 升级成结构化错因，让错题本能开出"药方"而不只是"名单"。

### 交互形态

答错后，解析区下方追加一行标签（同样是点选，可跳过）：

```
┌────────────────────────────────────────┐
│  ✗ 答错了                            │
│  正确答案：C. 说明截止时间，请求挪到明天│
│  ─────────────────────────────────    │
│  [解析原文] …                          │
│                                        │
│  这次错在哪儿？（可跳过）                │
│  ┌────────┐┌────────┐┌────────┐        │
│  │概念混淆 ││没记住  ││审题失误 ││ …    │
│  └────────┘└────────┘└────────┘        │
└────────────────────────────────────────┘
```

### 数据结构改动

```js
// 改动前
state.wrongBook[id] = true

// 改动后
state.wrongBook[id] = {
  n: 3,                 // 累计答错次数（替代原来只能增删的布尔）
  rs: ['mix', 'blur'],  // 错因集合，可多选
  last: 1752000000000   // 最近答错时间
}
```

### 错因标签集（固定 6 个，不自造）

| 标签 | 含义 |
|------|------|
| `mix` 概念混淆 | 和别的知识点搞混了 |
| `blur` 没记住 | 压根不记得 |
| `misread` 审题失误 | 看错/误解题干 |
| `guess` 犹豫蒙的 | 纯猜 |
| `over` 过度推理 | 想多了，书中没这层意思 |
| `spill` 场景迁移错 | 概念懂但场景应用错（scenario/case 专属） |

固定标签集的好处：可统计、可横向比较、可排序，不需要用户自由输入。

### 派生能力

首页新增一行「弱点画像」，仅用点选呈现：

```
你的错因分布    概念混淆 ████████ 42%   ← 主要矛盾
                没记住   ███ 18%
                审题失误 ██ 11%
                场景迁移 █████ 29%
按章节展开：第 3 章 错 12 次 ｜ 第 5 章 错 3 次
```

并可据此生成**定向练习**：只挑「概念混淆」标签 + 指定章节的题。

### 涉及改动

| 文件 | 改动 |
|------|------|
| `assets/考试系统_模板.html` | 新增 `setReason(tag)`；`finishGrading()` 写入新结构；`loadState()` 迁移；首页加弱点画像区 |
| `tools/regression_test.js` | **新增 2 项**：`setReason()` 写入正确、布尔旧数据能被迁移 |

### 验收标准
- 旧版 `wrongBook[id]===true` 能迁移为 `{n:1, rs:[], last:0}`
- 「错题重考」入口在迁移后仍能正常取到题
- 弱点画像的百分比之和为 100%
- 键盘 `Esc` 可跳过归因，不强制作答

## 三、间隔重复重考（优先级 3）

### 解决什么
正面解决短板 2。给每个知识点一个"下次该复习"的时间。

### 核心机制

按 Leitner 盒制简化，5 档：

| 盒 | 含义 | 下次可考时间 |
|----|------|------------|
| 1 | 新错/答错 | 立即 |
| 2 | 答对 1 次（蒙的） | 1 天后 |
| 3 | 答对 2 次（真懂） | 3 天后 |
| 4 | 答对 3 次 | 7 天后 |
| 5 | 答对 4 次+ | 30 天后 |

**升级规则**：真掌握（对 + 有把握）升 1 盒；蒙对（对 + 蒙的）**原地不动**；答错降 2 盒并入错题本。

### 交互形态

首页入口区新增一项，与现有四个并列：

```
▶ 正式考试      🎯 应用题专项      🔁 错题重考 (12)
📖 浏览模式     ⏰ 今日复习 (18)   ← 新增
```

点「今日复习」→ 只出 `t` 字段早于到期时间的题；没有到期题时明确提示：
> 现在没有到期的复习题。最近一次考试在 X 天前，下次复习时间：YYYY-MM-DD。

### 数据结构改动

```js
state.answered[id] = { r, c, t, box: 2, due: 1752172800000 }
```

### 涉及改动

| 文件 | 改动 |
|------|------|
| `assets/考试系统_模板.html` | `updateBox(id, correct, confident)`；`duePool()`；首页入口 + 空态文案 |
| `tools/regression_test.js` | **新增 3 项**：盒子升降规则、到期筛选正确、边界（无到期题不报错） |

### ⚠️ 必须先回答的两个问题

1. **惰性存档**：如果用户一周不打开网页，到期后堆积 200 题。是全给还是每次给 20 题？
   → 建议每次上限 20 题，按逾期时长排序。
2. **是否强制**：不强制。这是可选入口，不强制打断。

### 验收标准
- 连续答对 4 次的题从"今日复习"队列消失
- 蒙对 1 次的题仍在队列内（原地不动生效）
- 答错的题立即回到队列
- 无到期题时显示明确空态，不弹 `alert`

## 四、选项逐个追问（优先级 4）

### 解决什么
现在 `explanation` 是一条整段文字，说不清"我当时为什么会选那个错的"。
点开每个错误选项单独看，才知道自己跟它错在哪。

### 交互形态

```
✗ 答错了   ✅ C 正确
────────────────────────────────
你想选的 B 为什么不对？
  > 讨论会压缩到四十分钟，会议期间回复零散消息
    干扰项来自第 2 章「切换成本」——把会议和深度工作混在同一时段，
    即使缩短时长仍然挤压了高能量窗口。

[ 继续看其他错误选项 ]
```

### 关键前提：数据从哪来

⚠️ **这是四项里唯一需要动题库的**。两种做法：

**方案 A：卡片加可选字段（推荐）**

```json
{
  "id": "x01-01",
  "options": ["A. …", "B. …", "C. …", "D. …"],
  "optionWhy": {
    "A": "来自第 3 章「沉没成本谬误」——用已投入的时间为继续硬撑辩护。",
    "B": "来自第 2 章「切换成本」——缩短时长但仍与深度工作争抢同一时段。"
  }
}
```

- `optionWhy` 是**可选**字段，缺省时该选项不显示追问链接 → **完全向后兼容，360 道老题无需重写**
- 但要真正用起来，需要为 360 题补 `optionWhy`，这是一笔可观的子代理工作量

**方案 B：不改题库，自动生成**

从干扰项的 `tags` 反查它来自哪一章，展示一句"这个说法对应第 X 章的 Y 概念"。
零工作量，但解释质量不如手写。

### 我的建议
先做方案 B 的**降级版**——不写 `optionWhy`，只显示"该干扰项出自第 X 章"，
用现有数据就能跑，同时**在 schema 里预留 `optionWhy` 字段**。
以后想升级成方案 A，只补数据不改代码。

### 验收标准
- 无 `optionWhy` 的题，点击显示"该干扰项来自第 X 章"，不报错
- 有 `optionWhy` 的题，显示手写解释
- 正确选项不可点（无需追问）

## 五、键盘全覆盖（优先级 5）

### 现状

```js
document.addEventListener('keydown', e=>{
  if(document.getElementById('exam').classList.contains('hidden')) return;
  if(e.key==='Enter' || e.key===' '){ ... }
  if(['1','2','3','4','5','6'].includes(e.key)){ ... }
});
```

只有 `1`–`6` 和回车/空格。且**没有 `e.metaKey`/`e.ctrlKey` 防护**——
在浏览器里按 `Ctrl+1` 切标签页之类的组合键可能误触发答题。

### 扩展清单

| 键 | 作用 |
|----|------|
| `1`–`6` | 选选项（已有） |
| `Q` / `W` | 置信度：有把握 / 蒙的（新增） |
| `Enter` / `Space` | 下一题（已有） |
| `←` / `→` | 上一题 / 下一题（**需新做回退能力**） |
| `R` | 揭晓答案（等价于浏览模式看解析） |
| `M` | 标记本题（进收藏夹） |
| `Esc` | 跳过归因 / 退出考试 |

### ⚠️ 隐藏成本
`←` 上一题需要**回退能力**——当前 `exam.idx` 只增不减，
回退意味着要重放已答结果（否则回到上一题会看到空白）。
这是**唯一改动触及答题内核的一项**，风险最高，建议放在最后做或先不做。

### 另需修的既有缺陷

```js
document.addEventListener('keydown', e=>{ ... })   // 缺修饰键防护
```

建议加一行 `if(e.ctrlKey || e.metaKey || e.altKey) return;`。
这是个真实的小 bug，顺手修掉。
